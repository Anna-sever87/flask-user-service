# Аудит файла api.py

Аудит выполнен с помощью ИИ-ассистента (Claude): проверены безопасность, логика, стиль и устойчивость кода. Исходная версия сохранена в `audit/api_before.py`, исправленная находится в `api.py`.

## Найденные проблемы

| № | Критичность | Проблема | Чем опасна | Как исправлено |
|---|---|---|---|---|
| 1 | Высокая | Запуск с `debug=True` на `host="0.0.0.0"` | Отладчик Flask доступен по сети и позволяет выполнять код на компьютере | `debug=False`, адрес по умолчанию `127.0.0.1`, для Docker адрес задаётся переменной `HOST` |
| 2 | Высокая | SQL-инъекция в `/adduser` (запрос собран f-строкой) | Имя с апострофом ломает запрос (ошибка 500), а специально составленный текст меняет логику запроса | Параметризованный запрос `INSERT ... VALUES (?)` |
| 3 | Высокая | SQL-инъекция в `/user/<uid>` (конкатенация строк) | `/user/0 OR 1=1` возвращает первого пользователя вместо «не найдено», `/user/abc` даёт ошибку 500 | Параметризованный запрос и маршрут `<int:uid>` |
| 4 | Средняя | Одно глобальное соединение и курсор на всё приложение (`check_same_thread=False`) | Одновременные запросы делят один курсор, возможны сбои и повреждение данных | Соединение на каждый запрос (`flask.g`) с автоматическим закрытием |
| 5 | Средняя | Голый `except:` при создании таблицы | Скрывает любые ошибки, а не только «таблица уже есть» | `CREATE TABLE IF NOT EXISTS` |
| 6 | Средняя | Нет проверки входных данных (`request.json`) | Не-JSON даёт ошибку 415, пустое или огромное имя попадает в базу | `get_json(silent=True)`, проверка типа, пустоты и длины (до 100 символов), ответ 400 |
| 7 | Средняя | Общий список `active` без блокировки, ответ уходит раньше, чем поток закончит работу | Гонка потоков: список портится, в ответе нет только что добавленного пользователя | Класс `ActiveUsers` с блокировкой и ограничением размера, пользователь добавляется сразу |
| 8 | Средняя | Тяжёлая работа в обработчике `/slow` | Запрос и рабочий процесс заняты, остальные клиенты ждут | Задача в фоновом потоке, мгновенный ответ 202 |
| 9 | Средняя | `/wrong`: ошибка проглатывается, клиент получает 200 | Сбой незаметен, клиент считает ответ успешным | Перехват конкретного `ZeroDivisionError`, запись в журнал, ответ 500 |
| 10 | Средняя | Неверные коды HTTP | 200 для «не найдено», 201 вместо 200 при чтении, ответ `ok` текстом без кода создания | Коды 404, 200, 201 по смыслу, ответы в JSON |
| 11 | Низкая | Ошибки 404 и 405 отдаются в HTML | Клиент API не может их разобрать | Общие обработчики, единый формат `{"error": ..., "detail": ...}`; непредвиденные ошибки не раскрывают внутренности |
| 12 | Низкая | Файл базы `test.db` зашит в код | Нельзя поменять путь без правки кода (важно для Docker) | Путь берётся из переменной окружения `DB_PATH` |
| 13 | Низкая | Нарушения PEP 8, плохие имена (`addUser`, `GETUSER`, `q`, `r`, `cur`, `conn`), неиспользуемый `import random`, нет докстрингов и аннотаций | Код трудно читать и поддерживать | Имена исправлены, добавлены аннотации типов и докстринги |
| 14 | Низкая | Нет журнала работы | Нельзя понять, что произошло при сбое | Журнал через `logging` |

## Что добавлено

- `/health` - проверка работоспособности (нужна для Docker и мониторинга);
- `create_app()` - приложение создаётся функцией, что удобно для тестов;
- `check_service.py` - проверка всех эндпоинтов по HTTP;
- `requirements.txt` - зависимости проекта.

## Как проверяется

`check_service.py` выполняет 14 проверок: создание пользователя, апостроф в имени (защита от SQL-инъекции), пустое имя, не-JSON, поиск пользователя, 404, попытка инъекции `0 OR 1=1`, активация, фоновая задача, ожидаемая ошибка 500, 404 и 405 в формате JSON.

## Оставшиеся ограничения (учебный проект)

- Нет аутентификации и ограничения частоты запросов.
- Список активных пользователей хранится в памяти и сбрасывается при перезапуске. При нескольких процессах сервера у каждого был бы свой список, поэтому в Docker запускается один процесс.
- SQLite подходит для демонстрации, для большой нагрузки нужна полноценная СУБД.
