# Flask User Service: аудит кода с помощью ИИ и запуск в Docker

Домашнее задание к уроку 11 (программа «Вайб-кодер»): аудит небезопасного Flask-API с помощью ИИ, применение правок, проверка запуска, README, файл зависимостей и упаковка сервиса в Docker.

## Что сделано

- Взят учебный файл с намеренно допущенными ошибками (`audit/api_before.py`).
- ИИ-ассистент (Claude) провёл аудит: найдено 14 проблем, из них 3 серьёзные (отладчик Flask, доступный по сети, и две SQL-инъекции). Полный отчёт с таблицей проблем и исправлений: [audit/AUDIT.md](audit/AUDIT.md).
- Правки применены, исправленная версия лежит в `api.py`.
- Написан скрипт `check_service.py`, который проверяет все эндпоинты по HTTP (14 проверок).
- Добавлены `requirements.txt`, `Dockerfile` и `.dockerignore`, образ собран и запущен локально, сервис проверен внутри контейнера.

## Эндпоинты

| Метод | Адрес | Что делает | Коды ответов |
|---|---|---|---|
| GET | `/health` | проверка работоспособности | 200 |
| POST | `/adduser` | добавить пользователя, тело `{"name": "..."}` | 201, 400 |
| GET | `/user/<id>` | получить пользователя | 200, 404 |
| GET, POST | `/activate/<id>` | отметить пользователя активным, вернуть список последних 5 активных | 200, 404 |
| GET | `/slow` | запустить тяжёлую задачу в фоне | 202 |
| GET | `/wrong` | пример обработки ошибки (деление на ноль) | 500 |

Все ошибки возвращаются в формате JSON: `{"error": "код", "detail": "пояснение"}`.

## Запуск без Docker

Windows PowerShell:

```
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python api.py
```

Сервис будет доступен на http://127.0.0.1:8080. Проверка (в другом окне терминала с включённым окружением):

```
python check_service.py
```

## Запуск в Docker

Нужен установленный и запущенный Docker Desktop.

```
docker build -t flask-user-service .
docker run --rm --name user-service -p 127.0.0.1:8080:8080 flask-user-service
```

Сервис будет доступен на http://127.0.0.1:8080 (порт открыт только на вашем компьютере). Проверка в другом окне терминала:

```
python check_service.py
```

Внутри контейнера сервис запускает gunicorn с одним процессом и четырьмя потоками (список активных пользователей хранится в памяти процесса). Контейнер работает не от root, а Docker сам проверяет адрес `/health`, и статус `healthy` виден в `docker ps`.

## Настройки (переменные окружения)

- `DB_PATH` - путь к файлу базы SQLite (по умолчанию `users.db`, в Docker `/app/data/users.db`)
- `HOST` - адрес для локального запуска (по умолчанию `127.0.0.1`)
- `PORT` - порт для локального запуска (по умолчанию `8080`)

## Результат проверки

Скрипт `check_service.py` выполнил 14 проверок и локально, и в контейнере: все пройдены. Проверяются создание пользователя, апостроф в имени (защита от SQL-инъекции), пустое имя, не-JSON, поиск, ответ 404, попытка инъекции `0 OR 1=1`, активация, фоновая задача, ожидаемая ошибка 500, 404 и 405 в формате JSON.

## Ограничения

- Учебный проект: нет аутентификации и ограничения частоты запросов.
- База SQLite хранится внутри контейнера и пропадает при его удалении.
- Список активных пользователей хранится в памяти и сбрасывается при перезапуске.
- Не выполнены необязательные части задания: публикация образа в Docker Hub, развёртывание на сервере и документация OpenAPI.
- Аудит выполнен ИИ-ассистентом в чате (Claude), а не в Cursor; правки применены в VS Code.
